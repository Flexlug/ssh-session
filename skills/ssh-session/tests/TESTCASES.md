# sshsess — тест-кейсы

Смоук-набор для `scripts/sshsess.py`. Выполняется **только против локального
sshd** из `tests/local-sshd.sh`. Никаких удалённых хостов: на боевые машины
лезть нельзя, и тесты специально устроены так, чтобы этого не требовалось.

## Подготовка

```bash
SKILL=$(dirname "$(find ~/.claude ~/.config .claude -path '*ssh-session/scripts/sshsess.py' 2>/dev/null | head -1)")/..
bash "$SKILL/tests/local-sshd.sh" start
S="$SKILL/scripts/sshsess.py"
C=/tmp/sshsess-test/ssh_config
```

Локальный login shell — fish, поэтому рабочие сессии открываются так (кейс F3
проверяет как раз обратное — что без `--shell` приходит понятный отказ):

```bash
$S new NAME local-test --shell 'bash -i' -- -F $C
```

Правила исполнения:

- **Имена сессий начинай с префикса своей группы** (`a-`, `b-`, …). Параллельно
  работают другие исполнители, а имя сессии — общий ресурс машины.
- **Не вызывай `kill --all` и `prune`** — снесёшь чужие сессии. Убирай только
  свои, по имени.
- **`local-sshd.sh stop` не вызывай.** Узнать, что ты последний, исполнитель не
  может; стенд останавливает тот, кто раздавал задания.
- Оболочка вызовов — zsh (`$0` = `/usr/bin/zsh`; `Shell: /bin/fish` в окружении
  — это login shell пользователя, не оболочка вызовов). zsh **не** делает
  word-splitting: `-- $ARGS` подставится одним словом и ssh ответит
  `Bad port '…'`. Пиши `-- -F $C`, не собирай аргументы в переменную.
- Конструкция `VAR=value $S …` (нужна в E6/E7) в zsh работает; если исполняешь
  через fish — оберни в `bash -c`.
- Не используй `pkill -f` / `pgrep -f` с шаблоном, который встречается в твоей
  же командной строке: он совпадёт сам с собой и убьёт твой вызов. Здесь
  «удалённый» хост — localhost, так что это особенно легко устроить.
- Кейсы, где локаль влияет на текст (`ls /nope`, `jobs`), проверяй по **коду
  возврата и факту наличия сообщения**, а не по английской формулировке: на этой
  машине сообщения русские.
- Каждый кейс — отдельный проверяемый факт. Фиксируй **фактический** вывод и
  код возврата, не пересказывай ожидание. Расхождение — это находка, а не повод
  «поправить» тест.

## A. Жизненный цикл

| ID | Что проверяем | Как | Ожидаемо |
|---|---|---|---|
| A1 | sshd поднят только на loopback | `ss -tln \| grep 2222` | в колонке **Local Address** — `127.0.0.1:2222`. `0.0.0.0:*` в строке есть всегда, это колонка Peer Address |
| A2 | сессия открывается | `$S new a-1 local-test --shell 'bash -i' -- -F $C` | `session 'a-1' ready`, код 0 |
| A3 | `info` живой сессии | `$S info a-1` | есть target, `live`, owner, pty, путь к логу |
| A4 | `ls` показывает сессию | `$S ls` | строка `a-1 live … same owner` |
| A5 | состояние живёт между вызовами Bash | `run a-1 'cd /tmp'` в одном вызове, `run a-1 'pwd'` в **другом** | `/tmp` |
| A6 | `kill` закрывает | `$S kill a-1; $S ls` | `killed 'a-1'`, затем `a-1 dead` |
| A7 | `info` мёртвой сессии полезен | `$S info a-1` | код 3, но напечатан путь к логу и `ssh_exit` |
| A8 | мёртвое имя переиспользуется без `--force` | `$S new a-1 local-test --shell 'bash -i' -- -F $C` | код 0 |
| A9 | занятое живое имя не отдаётся | `$S new a-1 …` повторно | код 2, текст `is already running`, сессия цела |
| A10 | `--force` вытесняет живую | сначала `run a-1 'cd /etc; pwd'` → `/etc`; затем `new … --force`; затем `run a-1 'pwd'` | код 0, `pwd` = домашний каталог. Без первого шага кейс проходит вакуумно: сессия и так стоит в `$HOME` |
| A11 | неверное имя отклоняется | `$S new 'a/1' local-test -- -F $C` | код 2, `invalid session name` |
| A12 | `kill` несуществующей не врёт | `$S kill a-nope` | код **3**, `no such session 'a-nope'`. Ложное `killed 'a-nope'` с кодом 0 — это FAIL |
| A13 | `kill` уже мёртвой | `$S kill a-1` дважды | второй раз: `'a-1' was already dead`, без трейсбека |

## B. Корректность `run`

| ID | Что проверяем | Как | Ожидаемо |
|---|---|---|---|
| B1 | вывод чистый | `$S run b-1 'echo hi'` | ровно `hi` — без приглашения, эха, маркеров `__SS…` |
| B2 | коды возврата | `false` → 1, `ls /nope` → 2, `sh -c 'exit 7'` → 7, `nosuchcmd` → 127 | все совпадают |
| B3 | cwd и env сохраняются | `run 'cd /tmp && export Z=42'`, затем `run 'pwd; echo Z=$Z'` | `/tmp` и `Z=42` |
| B4 | stderr тоже приходит | `$S run b-1 'ls /nope'` | текст ошибки в stdout вызова |
| B5 | большой вывод не бьётся | `$S run b-1 'seq 1 20000' \| md5sum` — md5 считать **локально** по полученному потоку, сравнить с `seq 1 20000 \| md5sum` | md5 совпадают. Считать md5 удалённо нельзя: наружу придут 34 байта, и кейс прошёл бы даже при обрезке вывода |
| B6 | длинная строка не переносится | `$S run b-1 'printf "%3000s" "" \| tr " " x' \| tr -d '\n' \| wc -c` — длину мерить **локально** | `3000`. Удалённый `wc -c` не может обнаружить перенос на 200-й колонке pty, ради которого кейс написан |
| B7 | юникод | `run 'echo "Привет — ёжик 日本語 🚀"'` | строка целая |
| B8 | флаги команды не съедаются | `$S run b-1 ls -la /etc/hostname` | вывод `ls -la`, не ошибка argparse |
| B9 | завершающий `&` | `run 'sleep 30 &'`, затем `run 'jobs'` | код 0, в `jobs` видна задача |
| B10 | составные конструкции | `run 'for i in 1 2 3; do echo n$i; done'` | три строки |
| B11 | кавычки сохраняются | `run 'echo "a  b"; echo '"'"'c$d'"'"''` | двойной пробел цел, `$d` не раскрыт |
| B12 | пустой вывод | `run 'true'` | **0 байт** (не перевод строки), код 0 |
| B13 | таймаут | `$S run --timeout 2 b-1 'echo pre; sleep 30'` | код 124, в выводе `pre`, сообщение про partial, в выводе нет `__SS` |
| B14 | восстановление после таймаута | **сразу после B13**: `$S interrupt b-1`, затем `run b-1 'echo ok'` | `ok`, код 0. Вне связки с B13 кейс вырождается в обычный `echo` |
| B15 | порядок аргументов | `$S run b-1 --timeout 5 'echo x'` | код **127**, `bash: --timeout: command not found` — весь хвост стал удалённой командой, `x` не печатается. Контроль: `run --timeout 5 b-1 'echo x'` → `x`, код 0 |

## C. Защита от закрытия сессии

| ID | Что проверяем | Как | Ожидаемо |
|---|---|---|---|
| C1 | `exit` отклоняется | `$S run c-1 'exit 42'` | код 2, `refusing to run this`, сессия **жива** |
| C2 | `logout` отклоняется | `$S run c-1 'logout'` | код 2 |
| C3 | `exit` в цепочке | `$S run c-1 'ls /nope || exit 1'` | код 2 (тоже убило бы сессию) |
| C4 | субшелл разрешён | `$S run c-1 '(exit 42)'` | код **42**, сессия жива |
| C5 | `sh -c` разрешён | `$S run c-1 "sh -c 'exit 7'"` | код **7**, сессия жива |
| C6 | слово в строке — не команда | `$S run c-1 'echo "слово exit внутри"'` | код 0, строка напечатана |
| C7 | явное разрешение работает | `$S run --allow-exit c-1 'exit 9'` | код **0** и `session 'c-1' closed by request` — без аварийного дампа. Дальше `run c-1` → код 3, `ls` → `dead` |

## D. `send` / `read` / `wait`

| ID | Что проверяем | Как | Ожидаемо |
|---|---|---|---|
| D1 | `send --wait` показывает только новое | заранее засеять лог строкой-маркером, затем `$S send d-1 'echo scoped' --wait 1` | видно `scoped` (плюс эхо команды и приглашение — это нормально), но **не** засеянного маркера и не всего лога с начала |
| D2 | вход в REPL | взять офсет `read d-1 --offset` (он идёт в **stderr**), затем `send d-1 'python3 -q'`, затем `wait d-1 '>>>' --since OFFSET` | `>>>` найден, код 0. Без `--since` есть гонка: `wait` видит только байты после своего старта, и если приглашение успело прийти раньше — кейс висит весь таймаут |
| D3 | многострочный блок в REPL | `send d-1 --paste 'def fib(n):\n    …'` **одним аргументом с настоящими переводами строк**, затем `send d-1 '' --wait 1`, затем `send d-1 'fib(30)' --wait 2` | `832040`. Без `--paste` на Python ≥3.13 будет `IndentationError`: PyREPL сам добавляет отступ каждой строке продолжения |
| D4 | выход из REPL | `send d-1 --key C-d`, затем `run d-1 'echo back'` | `back`, код 0 |
| D5 | `read --tail` | `$S read d-1 --tail 5` | не больше 5 строк |
| D6 | служебные маркеры скрыты | `$S read d-1 --tail 30` и `--tail 30 --no-filter` | в первом нет `__SS…`, во втором есть |
| D7 | `--raw` отдаёт сырое | `$S read d-1 --raw \| cat -v \| grep -c '\^\['` | больше нуля. `\| head` не годится: в начале лога только `^M`. Доп. проверка: в выводе **без** `--raw` вхождений `^[` быть не должно |
| D8 | `--since` | `$S read d-1 --offset 2>/tmp/off >/dev/null`, взять число из `/tmp/off`, затем `read --since $OFF --all` | только вывод после офсета. `--offset` печатается в **stderr**; без `--all` к `--since` применяется ещё и `--tail 100`. Не пиши `$(… 2>&1 >/dev/null \| …)`: в zsh с MULTIOS stdout попадёт в ту же подстановку и в офсет уедут цифры из лога |
| D9 | `wait` ждёт **новый** вывод | `send d-1 'for i in 1 2 3 4 5; do echo step-$i; sleep 1; done'`, затем `time $S wait d-1 'step-5'` | нашёл, заняло **≈4 s** (`step-5` печатается после четвёртого `sleep`). Мгновенный ответ = FAIL: поймано эхо |
| D10 | `wait` по таймауту | `$S wait d-1 'НИКОГДА' --timeout 3` | код 124 |
| D11 | `wait --from-start` | искать строку, которая уже была в логе | находит мгновенно |

## E. Параллельность и изоляция

| ID | Что проверяем | Как | Ожидаемо |
|---|---|---|---|
| E1 | сессии независимы | в `e-1` `cd /tmp`, в `e-2` `cd /etc`, затем `pwd` в обеих | `/tmp` и `/etc` |
| E2 | реальная параллельность | в `e-1` фоновая задача пишет строку раз в секунду 12 s; из `e-2` **одним** `run` три замера с удалённым `sleep 3` между ними | счётчик строк растёт минимум трижды (напр. 1→5→9), `e-1` при этом отвечает на `run`. Важно: «удалённое» здесь = localhost, файловая система общая, поэтому рост файла сам по себе не доказывает удалённость — доказывает `run` в занятой `e-1` |
| E3 | гонка в одну сессию сериализуется | два `run` в `e-1` одновременно (`&` в локальном shell), вывод в разные файлы; замерить общее время | каждый файл **побайтово равен** своему ожидаемому выводу, 0 чужих строк, 0 вхождений `__SS` и `{ printf`. Оба кода 0. Время ≈ сумме длительностей (параллельное исполнение дало бы половину) — это и есть доказательство сериализации |
| E4 | занятость видна | пока `run e-1 'sleep 5'` идёт, `$S run --timeout 1 e-1 'echo x'` | код 125, `is busy`, ответ приходит **через ≈1 s**, а не мгновенно: `--timeout` — общий бюджет на ожидание блокировки плюс выполнение |
| E5 | прерывание разблокирует `run` | `run --timeout 60 e-1 'echo pre; sleep 45'` в фоне, через 2 s `$S interrupt e-1` | `run` возвращается **сразу** с кодом **130**, сессия жива, блокировка снята (следующий `run` проходит мгновенно). Отдельно: `send --key C-c` прерывает удалённую команду, но `run` при этом досиживает таймаут и отдаёт 124 — это документированное поведение, а не то же самое |
| E6 | владельцы различаются | `SSHSESS_OWNER=x $S new e-3 …`, затем `SSHSESS_OWNER=y $S ls` | `e-3` помечена `other:x` |
| E7 | чужое имя не захватывается | `SSHSESS_OWNER=y $S new e-3 …` | код 2, упомянут другой владелец. Известная дыра: `--force` проверку владельца обходит — зафиксируй это как факт, а не как FAIL |

## F. Ошибки и диагностика

| ID | Что проверяем | Как | Ожидаемо |
|---|---|---|---|
| F1 | несуществующая сессия | `$S run f-nope 'echo x'` (имя, которое **никогда** не создавалось — каталога сессии нет) | код 3, `is not running`, **без трейсбека**. Проверь заодно `send`/`wait`/`info` на том же имени |
| F2 | плохой аргумент ssh | `$S new f-1 local-test --timeout 8 -- -F $C --bogus-flag` | код 3, показана строка запуска ssh и его вывод |
| F3 | не-POSIX login shell | `$S new f-2 local-test --timeout 12 -- -F $C` (**без** `--shell`) | код 4, подсказка `--shell 'bash -i'` с готовой командой |
| F4 | команда, читающая stdin | `$S run --timeout 6 f-3 'read x'` → код 124; затем **обязательно** `$S interrupt f-3`; затем `run f-3 'read x < /dev/null; echo rc=$?'` | без `interrupt` висящий `read` съедает первую строку обёртки следующей команды и она тоже падает — это ожидаемое поведение, а не баг |
| F5a | обрыв во время `run` | `run f-5 'sleep 60'` в фоне, затем `kill <ssh_pid>` (pid из `info`) | код 3 и хвост лога в сообщении |
| F5b | обрыв до `run` | убить ssh, дождаться, затем `run` | код 3 `no live socket` — хвоста здесь быть не может, демон уже снял сокет; хвост смотреть через `info` |
| F6 | несуществующий хост | `$S new f-4 no-such-host.invalid --timeout 8` | код 3, в дампе видна строка `ssh: Could not resolve hostname …`. Пустой дамп = FAIL (однострочные ошибки ssh приходят как `\r\r\n` и раньше терялись) |
| F6b | отказ в соединении | `$S new f-6 127.0.0.1 --timeout 8 -- -p 2223` (закрытый порт) | в дампе `Connection refused` |
| F7 | дампы ошибок короткие | посмотреть сообщение любого падения | хвост ≤ 12 строк (весь блок ~15 со шапкой и разделителями), 0 вхождений `__SS…`. Критерий относится к сообщениям об ошибках; partial-вывод `run` при таймауте проверяется отдельно в B13 |

## H. Промпты: чтобы работа не встала

Фикстуры (создать перед группой; настоящие пароли не используются):
`fake-sudo.sh` спрашивает пароль с выключенным эхом и принимает `s3cr3t-test-pw`,
`fake-apt.sh` печатает `Do you want to continue? [Y/n] `, `fake-press.sh` —
`Press ENTER to continue... `. В `~/.config/sshsess/secrets.json` (режим 0600):
`{"secrets": {"sudo": "s3cr3t-test-pw"}}`.

| ID | Что проверяем | Как | Ожидаемо |
|---|---|---|---|
| H1 | гашение применяется | `new h-1 … ` затем `run h-1 'echo $PAGER $EDITOR $DEBIAN_FRONTEND'` | сообщение `(non-interactive env applied)`, значения `cat false noninteractive` |
| H2 | пейджер залипает без гашения | `new h-2 … --no-harden`, затем `run --timeout 6 h-2 'cd <git-репо> && git log'` | код 124, в выводе виден промпт пейджера. Затем `interrupt` |
| H3 | с гашением пейджер не мешает | `run --timeout 10 h-1 'cd <git-репо> && git log \| tail -2'` и `run h-1 'systemctl status sshd 2>&1 \| tail -2'` | код 0 оба |
| H4 | пароль подставляется из файла | `run --timeout 10 h-1 fake-sudo.sh` | код 0, `AUTH_OK`, в stderr `auto-answered sudo-password -> <secret:sudo>` |
| H5 | пароль не утекает в лог | `read h-1 --all --no-filter \| grep -c s3cr3t` и `read h-1 --raw \| grep -ac s3cr3t` | **0** и **0** |
| H6 | подтверждения не отвечаются без `--yes` | `run --timeout 6 h-1 fake-apt.sh` | код 124 (промпт остался без ответа). Затем `interrupt` |
| H7 | `--yes` отвечает подтверждение **один** раз | `run --timeout 10 --yes h-1 fake-apt.sh`, посчитать строки `auto-answered` | код 0, ровно **1** строка (не 2: альтернативы одного правила не должны срабатывать дважды на одной строке) |
| H8 | «Press ENTER» | `run --timeout 10 h-1 fake-press.sh` | код 0, `continued` |
| H9 | три промпта в одной команде | `run --timeout 20 --yes h-1 'fake-sudo.sh; fake-apt.sh; fake-press.sh'` | код 0, ровно 3 строки `auto-answered` |
| H10 | нет ложных срабатываний на выводе | `run --timeout 10 --yes h-1 'echo "Press ENTER to continue"; echo "Do you want to continue? [Y/n]"; echo done'` | код 0, **ни одной** строки `auto-answered`: это вывод, никто не ждёт |
| H11 | права на секреты проверяются | `chmod 644` на secrets.json, затем любой `run` | код 2, текст `is readable by others`. Вернуть `chmod 600` |
| H12 | отсутствующий секрет | правила с `"secret":"nonexistent"`, затем `run` на fake-sudo.sh | строка `PROMPT NOT ANSWERED -- … secret 'nonexistent' is not configured` (отдельно от `auto-answered`, чтобы подсчёт ответов не портился), затем код 124 |
| H13 | `expect` на уже залипшей сессии | `send h-1 fake-apt.sh`, подождать, затем `expect h-1 --dry-run --once --yes` | `would answer yes-no-confirm -> y`, ничего не отправлено |
| H14 | `expect` разблокирует | там же `expect h-1 --once --yes`, затем `run h-1 'echo ok'` | `answered …`, затем `ok` код 0 |
| H15 | одиночный символ как клавиша | `send h-1 --key q` | код 0, не `unknown key` |
| H16 | TUI-меню клавишами | `send h-1 'whiptail --menu … 2>/tmp/choice.txt'`, подождать, `send h-1 --key Down --key Enter`, затем `run h-1 'cat /tmp/choice.txt'` | второй пункт меню |
| H17 | `--list-rules` | `$S expect --list-rules` | **все 6** правил, код 0, без обращения к сессии; закрытые за `--yes` помечены `[needs --yes]` |
| H19 | пейджер `less -M` ловится | `--no-harden`-сессия, `run --timeout 12 'less -M /etc/services'` | код 0, одна строка `auto-answered pager -> <key:q>` (шаблон должен доедать хвост строки с процентами) |
| H20 | обычный `less` честно не ловится | там же `run --timeout 8 'less /etc/services'` | код 124 — имя файла в инверсии неотличимо от вывода. Выход: `send --key q` |
| H18 | `--no-auto` отключает | `run --timeout 6 --no-auto h-1 fake-sudo.sh` | код 124, ни одного `auto-answered` |

## I. Восстановление после залипания и обрыва

| ID | Что проверяем | Как | Ожидаемо |
|---|---|---|---|
| I1 | таймаут помечает сессию занятой | `run --timeout 4 i-1 'read x'` | код 124 |
